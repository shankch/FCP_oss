I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `pluck(arr)`, and `fcp lint` now reports `lint: clean`. Each cycle is one call: the argument is the input list `arr` (at most 8 numbers, 16 bits each, so 0 to 65,535, and it can be empty). The result is the output list `plucked` (at most 3 numbers of 16 bits), which leaves room for wrong-length answers of 1 or 3 elements as well as the allowed `[]` and `[value, index]`. `outcome` is 2 bits with `raises: []`, since the request names no exception: 0 a list that fits was returned, 1 any exception or no answer, 2 anything else. Both the `arr` and `plucked` bounds are narrower than what the request allows: it allows up to 10,000 nodes with no upper limit on values, but FCP-PL quantifiers stop at 256. So `frame.md` says longer lists, larger values and negative numbers are not part of the trace. The one frame rule, F-EMPTY (`outcome != 0 -> len(plucked) == 0`), cites R-FR-1, quoted verbatim from `frame.md` and anchored by `fcp anchor` to line 48. The `scope` uses the request's four example inputs as values and elements 0 to 5. I also left `draft.yaml` in the workspace as the input to the anchor step. One thing for whoever formalizes this: the request looks garbled, since "the node with the value" seems to be missing a word (likely "smallest even"), and its constraint of at least one node contradicts its own empty-list example. I described only the interface and didn't try to resolve either.
