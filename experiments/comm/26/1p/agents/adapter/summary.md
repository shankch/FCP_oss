I wrote `design.yaml`, `frame.md` and `requirements.yaml`, and `fcp lint` reports clean. Each cycle after the reset cycle is one call of `candidate(numbers)`, a stateless function. The argument goes on one list input, `numbers`, and the returned list goes on one list output, `result`. Both hold at most 8 numbers, each from 0 to 255; the request gives no bounds, so those limits are my choice. A 2-bit `outcome` records how the call ended: 0 if it returned a list that fits, 1 if it raised any exception or didn't finish, and 2 if it returned anything else. The request names no exception, so `raises` is `[]`. The `function` section also declares the list types, and its `scope` takes elements 0–4, 254 and 255 plus 3000 random lists. The small values are there so that lists with repeated numbers come up often. The documents are SPEC (`spec.md`) and FRAME (`frame.md`). There is one frame rule, F-EMPTY (`outcome != 0 -> len(result) == 0`), which cites R-FR-1, a verbatim quote of `frame.md` whose line number `fcp anchor` computed from `draft.yaml`. `frame.md` describes only the encoding: the call model, how lists appear in FCP-PL, the signal tables, and that longer lists, numbers above 255 and negative numbers are not part of the trace. The request's docstring is cut off ("remove all elements that occur."), and the encoding doesn't depend on what it was meant to say. `draft.yaml` is still in the workspace.
