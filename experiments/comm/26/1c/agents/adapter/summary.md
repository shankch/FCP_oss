I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `remove_duplicates(numbers: List[int]) -> List[int]`, and `fcp lint` reports the bundle clean. The function is treated as a chip without memory, so each cycle after the reset in cycle 0 is one independent call. The argument goes on the input list signal `numbers` and the returned list on the output list signal `result`. Each holds at most 8 integers from 0 to 255 (8 bits, `length: 8`). The request puts no limit on how long the list is or how big the numbers are, so those caps are my choice, made to keep the checks small. `frame.md` says that longer lists, numbers above 255 and negative numbers are not part of the trace. The 2-bit `outcome` signal uses `raises: []`, since the request names no exception: 0 means it returned a list that fits, 1 means any exception or no answer, and 2 means it returned anything else. The `function` section declares both values as `type: list`. Its scope uses elements 0 to 5, 3000 random lists and the docstring example `[1, 2, 3, 2, 4]`. Lint accepted the `elements` key there, but its format is my guess from the IR doc, and I haven't run anything that uses the scope. There is one frame rule, F-EMPTY (`outcome != 0 -> len(result) == 0`), which cites R-FR-1: a verbatim `definition` quote of `frame.md` that `fcp anchor` placed at line 46. `frame.md` also covers how lists are read in FCP-PL (`len`, `s[i]`, `x in s`) and warns that `s[i]` is 0 past the end of a list, while 0 can also be a real element.
