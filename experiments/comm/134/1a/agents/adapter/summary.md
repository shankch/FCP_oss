I wrote `design.yaml`, `frame.md` and `requirements.yaml`, and `fcp lint` now reports `lint: clean`. Each cycle after the reset in cycle 0 is one independent call of `candidate(txt)`. The argument `txt` is an input string signal of up to 32 characters, each 8 bits (Latin-1 codes 0–255); 32 is my choice, since the request sets no limit and its examples are at most 11 characters. The returned value goes on a 1-bit output `result`, and a 2-bit `outcome` says how the call ended. Because the request names no exception, `raises` is `[]`, so the codes are 0 returned True/False, 1 raised any exception or did not finish, and 2 returned anything else. The `function` section declares `candidate` with a `str` argument and a `bool` return. Its scope uses the four example strings (`"apple pie"`, `"apple pi e"`, `"apple pi e "`, `""`), plus 3000 random strings from a small alphabet of letters, a space, a digit and a full stop. `frame.md` explains the calls, the strings and the outcome codes without restating the request's rules. It also says longer strings and negative values are not part of the trace, and that FCP-PL's `isalpha` and `isspace` cover ASCII characters only (so `é` is not `isalpha`). There is one frame rule, F-ZERO (`outcome != 0 -> !result`), cited by R-FR-1 as a `definition` that quotes frame.md word for word.
