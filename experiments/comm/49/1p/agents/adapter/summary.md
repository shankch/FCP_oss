I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `modp(n, p)`, and `fcp lint` reports clean. Each cycle is one call of `modp`, and the function keeps no state between calls. The two arguments are the inputs `n` and `p`, each 10 bits (0 to 1,023). The returned value is the output `result`, also 10 bits. The 2-bit `outcome` signal uses 0 for a returned integer that fits, 1 for any exception or no answer, and 2 for anything else. Because the request names no exception, `raises` is `[]`. The request puts no limit on `n` or `p`, so the 0 to 1,023 range is my choice: `frame.md` says that negative arguments and arguments above 1,023 are not part of the trace. The `function` section has the name, the two `int` arguments, the returned value and the outcome. Its scope covers 0 to 100 for each argument plus 200 random values each, which includes the boundary values 0 and 1 for `p`. There is one frame rule, F-ZERO (`outcome != 0 -> result == 0`).
