I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `is_equal_to_sum_even(n)`, and `fcp lint` reports `lint: clean`. Each call is one cycle of a chip without memory, built like the `code_checkout` example. The argument goes on a 16-bit input `n` (0 to 65,535). The return value goes on a 1-bit output `result`, and a 2-bit `outcome` uses `raises: []` because the request names no exception: 0 means it returned True or False, 1 means any exception or no answer, and 2 means it returned anything else. I picked 16 bits myself, since the request sets no upper limit. `frame.md` says negative values and values above 65,535 are not part of the trace. The scope tests every `n` from 0 to 1000 plus 400 random values. There is one frame rule, F-ZERO (`outcome != 0 -> !result`), cited by R-FR-1: a verbatim quote of `frame.md` line 36, with the line number filled in by `fcp anchor` from `draft.yaml`, which I left in the workspace. I named the design `review` to match the `requirements.yaml` that was already there. Whoever formalizes this should know the request contradicts itself, though I left it out of the files: its examples say 4 and 6 give True and 8 gives False, but 8 = 2+2+2+2 is the smallest sum of four positive even numbers, so 4 and 6 can't be written that way.
