I wrote `design.yaml`, `frame.md` and the requirement in `requirements.yaml`, and `fcp lint` reports `lint: clean`. Each call of `eat(number, need, remaining)` is one cycle after a reset in cycle 0, with no state kept between calls. The three integer arguments are 10-bit inputs (0 to 1,023), which covers the request's 0–1000 range and the values just above it. The returned `[total eaten, carrots left]` is split into two output signals: `eaten` (11 bits, up to 2,047) and `left` (10 bits). The request names no exception, so `raises: []` and `outcome` takes 2 bits: 0 it returned two integers that fit, 1 any exception or no answer, 2 anything else. `frame.md` says negative arguments are not part of the trace and defines one frame rule, F-ZERO: `eaten` and `left` are 0 unless `outcome` is 0. That rule cites R-FR-1, whose line number (43) `fcp anchor` computed from `draft.yaml`, which I left in the workspace. The `scope` covers 0–12 densely (all the request's example values), plus 999, 1000, 1001 and 20 random values per argument. One thing I couldn't check: I described the result as two signals (`returns: {signals: [eaten, left]}`), and the IR spec only describes that form for tuples.
