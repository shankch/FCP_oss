I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `eat(number, need, remaining)`, and `fcp lint` reports no errors. Each call is one cycle with no memory between calls. The three arguments are 11-bit inputs (0 to 2,047); the request gives no bounds, so frame.md says that larger and negative arguments are not part of the trace. The request doesn't say what `eat` returns, so I made the result one sequence signal, `result`: a list of at most 4 numbers, each 13 bits (0 to 8,191, enough for any sum of the three arguments). If the code returns a single number, a tuple or anything else instead, the call is recorded as outcome 2 rather than a value. That's the one real judgement call here; if you know the code returns a pair, a two-signal tuple (`signals: [..]`) would be the alternative. Because the request names no exception, `raises` is `[]` and `outcome` is 2 bits (0 returned a list that fits, 1 any exception or no answer, 2 anything else). The `scope` has dense ranges 0–30 plus 300 random values per argument, since the request mentions no particular numbers. The only frame rule is F-EMPTY (`outcome != 0 -> len(result) == 0`), which cites R-FR-1.
