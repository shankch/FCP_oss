I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `candidate(arr)`, and `fcp lint` reports clean. Each cycle is one call of `candidate(arr)`. The argument `arr` is one input sequence signal (`type: list`) of up to 8 slots, each 8 bits wide, so a list of at most 8 integers from 0 to 255. The returned integer is the output `changes`, 4 bits wide (0 to 15), which holds every count up to the list length and values just above it. Since the request names no exception, `raises` is `[]` and `outcome` takes 2 bits: 0 means it returned an integer that fits, 1 any exception or no answer, and 2 anything else. The 8-element and 0–255 limits are my own picks, because the request allows any list of integers. The scope for `arr` draws elements from 0–3 and 254–255, with 3,000 random lists and a few fixed ones such as `[]`, `[1, 2, 1]` and `[1, 2, 3, 4, 3, 2, 2]`. `frame.md` explains the calls, how lists are carried and their FCP-PL notation, and the input and output tables. It states that longer lists, elements above 255 and negative integers are not part of the trace. It describes the interface only and doesn't restate the palindrome rule. The one frame rule, F-ZERO (`outcome != 0 -> changes == 0`), cites R-FR-1, a verbatim quote of `frame.md` whose line (47) `fcp anchor` computed from `draft.yaml`, which is still in the workspace.
