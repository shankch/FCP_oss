I wrote `design.yaml`, `frame.md` and `requirements.yaml` in the workspace for `smallest_change(arr)`, and `fcp lint` reports clean. Each call is one cycle: `arr` is a 4-bit input list of up to 10 elements (`type: list`, values 0 to 15). That covers the example lists (up to 8 elements, values 1 to 9) and the values just past them. The returned integer goes on a 4-bit output, `changes` (0 to 15), which holds the example answers 5, 7 and 8 and anything up to the list length plus one. The 2-bit `outcome` follows the examples' coding with `raises: []`, since the request names no exception: 0 means it returned an integer that fits, 1 means any exception or no answer, and 2 means it returned anything else. The `scope` has the three example lists as `values`, their numbers as `elements`, and 3000 random lists. `frame.md` explains how lists work in FCP-PL (`len`, `arr[i]`, list literals, `in`), gives the input and output tables, and says that negative integers, longer lists and elements above 15 are not part of the trace. Its one frame rule, F-ZERO (`outcome != 0 -> changes == 0`), cites R-FR-1, a verbatim quote of `frame.md` whose line number I got with `fcp anchor` from `draft.yaml`, which I left in the workspace.
