I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `is_happy(s)`, and `fcp lint` reports **clean**. Each cycle is one call with no memory between calls, as in `code_mask`. The argument becomes an input string signal `s` (8-bit Latin-1 codes, at most 16 characters). The return value becomes a 1-bit output `happy`. A 2-bit `outcome` uses `raises: []`, since the request names no exception: 0 means it returned True or False, 1 means any exception or no answer, and 2 means it returned anything else. I picked the 16-character limit myself because the request gives no length: it is well past the longest example (4 characters), and `frame.md` says longer strings are not part of the trace. The `function` section declares `is_happy` with a `type: str` argument and a bool return. Its `scope` uses the alphabet `abcdxy` with 3000 random strings plus the six example strings. `frame.md` explains the calls, how strings are encoded, the input and output tables, that signals are unsigned so no negative number appears in the trace, and the frame rules. There are two frame rules. `F-ZERO` (`happy` is false unless `outcome` is 0) follows the examples. I added `F-CODE` (`outcome` is never 3) because 2 bits can hold a code the encoding never produces. Each rule cites a `kind: definition` requirement (R-FR-1 and R-FR-2) quoting `frame.md` verbatim, with lines 47 and 48 filled in by `fcp anchor` from `draft.yaml`, which I left in the workspace. I named the design `review` to match the existing header in `requirements.yaml` rather than using a `code_<x>` name like the examples.
