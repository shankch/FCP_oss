I've written `design.yaml` and `frame.md` for `is_happy(s)`, added R-FR-1 to `requirements.yaml`, and `fcp lint` now reports clean. Each cycle after the reset is one call with no memory between calls. The argument `s` is an input string of up to 32 characters, each a code from 0 to 255; that length is my choice, the same bound as the code_mask example, since the request allows strings of any length. The returned boolean goes on a 1-bit output, `happy`. The 2-bit `outcome` signal uses the coding for a request that names no exception (`raises: []`): 0 it returned True or False, 1 it raised any exception or did not finish, 2 it returned anything else. The `function` section has a scope with the request's six examples (`a`, `aa`, `abcd`, `aabb`, `adb`, `xyy`), 3000 random strings and the alphabet `abcdxy`, which is the letters those examples use. `frame.md` covers the calls, how strings appear in FCP-PL, the inputs, the outputs and the encoding. It says that longer strings, characters above code 255 and negative numbers are not part of the trace. It describes the interface only, without restating the request's rules. It has one frame rule, F-ZERO (`outcome != 0 -> !happy`). R-FR-1 quotes that rule verbatim, with kind `definition`, and `fcp anchor` filled in its line (49). The draft I anchored from, `draft.yaml`, is still in the workspace.
