I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `simplify(x, n)`, and `fcp lint` reports "lint: clean". The main judgment call: neither the request nor the signature says what type the arguments or the result are, so I chose to pass `x` and `n` as strings and record the result as a boolean, because that is what this well-known prompt's code usually returns. This choice matters: if the code returns something else, such as a simplified fraction like `"1/25"`, every call will show as outcome 2 ("returned anything else") and the check will mean little. Switching the result to a string would mean changing the return signal and its row in `frame.md`. The two arguments are 8-bit sequence signals of up to 16 characters (codes 0–255), with one 1-bit `result` output. The 2-bit `outcome` uses `raises: []` because the request names no exception: 0 means it returned True or False, 1 means any exception or no answer, and 2 means anything else. The design is named `review` to match the existing `requirements.yaml`. The `function` scope draws both arguments from the characters `0123456789/` plus a few fractions, including `0/1` and the zero-denominator `1/0`. `frame.md` says the adapter chose these types, sets the 16-character and code-255 limits, and says other argument types are not part of the trace, including numbers (signals are unsigned, so negatives never appear). Its one frame rule is F-ZERO (`outcome != 0 -> !result`), cited by R-FR-1, a `definition` with `fcp anchor` placing the quote at line 53. The `draft.yaml` used for anchoring is still in the workspace.
