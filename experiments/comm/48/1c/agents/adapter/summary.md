I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `is_palindrome(text)`, and `fcp lint` reports no errors. The design treats the function as a chip without memory: each cycle after the reset is one call. `text` is an input string signal of up to 32 characters, each with a code from 0 to 255. Because the request puts no limit on length, 32 is my own choice; it covers the doctest strings (up to 5 characters) and well beyond. There are two outputs: `result` (1 bit, the returned True/False) and a 2-bit `outcome` (0 it returned a bool, 1 any exception or no answer, 2 it returned anything else). `raises` is `[]` because the request names no exception. The `function` section has a `scope` with the four doctest strings (`''`, `'aba'`, `'aaaaa'`, `'zbcd'`), the alphabet `abcdz` and 3000 random strings. `frame.md` follows the function-adapter examples: it explains the calls, how strings are written in FCP-PL, the input and output tables, and that longer strings, codes above 255 and negative values are not part of the trace. There is one frame rule, F-ZERO (`outcome != 0 -> !result`), which cites R-FR-1; that requirement is a definition quoting `frame.md` line 46, and `fcp anchor` filled in the line number from `draft.yaml`, which is still in the workspace. One thing for whoever formalizes this: the doctests in `spec.md` say `'aba'` and `'aaaaa'` give False and `'zbcd'` gives True, which is the opposite of what the name suggests. As instructed, I described only the interface and didn't interpret this.
