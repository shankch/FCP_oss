I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `candidate(text)`, and `fcp lint` now reports clean. Each cycle after the reset is one call with no memory between calls. The `text` argument is one input string of at most 32 characters (codes 0–255, `length: 32`). The result is a 1-bit `result` output, and a 2-bit `outcome` says how the call ended. Because the request names no exception, `raises` is `[]`: outcome 0 means it returned True or False, 1 means any exception or no answer, and 2 means it returned anything else. One frame rule, F-ZERO (`outcome != 0 -> !result`), cites R-FR-1, a definition quoting line 52 of `frame.md`, anchored with `fcp anchor` from `draft.yaml` (left in the workspace). `frame.md` covers the call model, the string encoding, the input and output tables, the outcome codes and the note that signals are unsigned, so negative integers are not part of the trace. Three choices are mine, because the request leaves them open: it is cut off mid-sentence ("Checks if given string is a ") and the signature has no return type. I read the return as a boolean because of "Checks if" (`frame.md` says the signature declares none). I picked 32 characters as the length limit, since the request gives none. The request names no values, so I filled the scope with random calls (3000) over a small alphabet `'abAB 1.'`, plus the empty string.
