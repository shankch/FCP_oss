I wrote `design.yaml`, `frame.md` and the requirement entry for `is_palindrome(text: str)`, and `fcp lint` reports clean. Each cycle after the reset in cycle 0 is one stateless call. The argument goes on a `text` input of up to 16 characters, each 8 bits wide (Latin-1 codes 0–255). The function has two outputs: a 1-bit `result` (1 means True) and a 2-bit `outcome`. Because the request names no exception, `raises` is `[]`, so `outcome` is 0 for a returned bool, 1 for any exception or no answer, and 2 for anything else returned. The `function` section's scope adds the four doctest strings (`''`, `'aba'`, `'aaaaa'`, `'zbcd'`), the alphabet `abcdz` and 3,000 random strings. There is one frame rule, F-ZERO (`outcome != 0 -> !result`). It cites R-FR-1, a definition that quotes frame.md line 46, with the line computed by `fcp anchor` from `draft.yaml`. `frame.md` explains the call model, how strings are encoded, and the two signal tables. It says longer strings, characters above code 255 and negative numbers are not part of the trace, and it does not restate the request's rules. The 16-character limit is my own choice, since the request puts no bound on length: it covers the doctests with room to spare and keeps the analyses cheap.
