I wrote `design.yaml`, `frame.md` and `requirements.yaml`, and `fcp lint` reports "lint: clean". The design models `fib4(n)` as a function with no memory: cycle 0 is reset, and every later cycle is one independent call. The argument goes on a 7-bit input `n` (0 to 127), the returned integer on a 128-bit output `result`, and how the call ended on a 2-bit `outcome`. Because the request names no exception, `raises` is `[]`, so `outcome` is 0 when it returned an integer that fits, 1 for any exception or no answer, and 2 for anything else. The request sets no upper limit on `n`, so 127 is my own cap; `frame.md` says that negative arguments and arguments above 127 are not part of the trace. I estimated by hand that `fib4(127)` takes about 118 bits, which leaves about 10 bits of room in `result`, because running Python to compute it exactly wasn't approved. The scope is `dense: [0, 127]`, which tries every allowed `n` and so includes 0–7, the values the request talks about. The one frame rule, F-ZERO (`outcome != 0 -> result == 0`), cites R-FR-1, a `definition` requirement quoting `frame.md` line 38; `fcp anchor` worked out the line from a draft file, which I then deleted. `frame.md` explains the encoding in the same layout as the examples and doesn't restate the request's rules.
