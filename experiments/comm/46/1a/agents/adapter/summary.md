I wrote `design.yaml`, `frame.md` and `requirements.yaml` (plus the `draft.yaml` that `fcp anchor` read), and they describe each cycle after reset as one independent call of `fib4(n)`. **Input:** `n` is 7 bits, so 0 to 127. The request sets no upper limit on `n`, so 127 is my choice; `frame.md` says that larger and negative `n` are not part of the trace. **Outputs:** `result` is 118 bits and is the returned integer when the call returns. `outcome` is 2 bits: 0 it returned an integer that fits, 1 any exception or no answer (`raises: []`, because the request names no exception), 2 anything else, including a negative number. **Why 118 bits:** whichever signs the recurrence's "+/-" takes, no value can be larger than what all plus signs give. For n = 127 that is about 2^117.5, so 118 bits holds every value the request allows. I worked this out by hand because running Python or awk needed approval; the result is about half a bit from the boundary, so it's safe. **Rest of `design.yaml`:** the `function` section has `name: fib4`, one `int` argument, an `int` return, and a scope of `n: {dense: [0, 127]}`, which covers every input the trace allows.
