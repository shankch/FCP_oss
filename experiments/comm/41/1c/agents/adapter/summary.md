I wrote the adapter files for `is_prime(n)` and `fcp lint` reports the bundle as clean. The request uses that function name but describes counting car collisions, so the encoding describes the interface only and doesn't restate that rule. Each cycle after the reset in cycle 0 is one independent call. The argument is the input signal `n`, 10 bits (0 to 1,023). The returned value is the output signal `collisions`, 20 bits (0 to 1,048,575). Both bounds are my choice, since the request sets none. The request names no exception, so `raises` is `[]` and the 2-bit `outcome` signal is coded 0 for an integer that fits, 1 for any exception or no answer, and 2 for anything else. The `function` section declares the name, the int argument and return, the outcome, and a scope that tries every `n` from 0 to 1,023, because the request mentions no specific values. `docs` lists SPEC (spec.md) and FRAME (frame.md). The one frame rule, F-ZERO (`outcome != 0 -> collisions == 0`), cites R-FR-1 in `requirements.yaml`, a verbatim quote of frame.md whose line was set by `fcp anchor` from `draft.yaml`; I left `draft.yaml` in the workspace. frame.md explains the calls, the widths, that negative and too-large arguments are not part of the trace, the outcome coding, and the frame rule.
