I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `car_race_collision(n)`, and `fcp lint` now reports clean. Each cycle after the reset in cycle 0 is one call with no memory between calls. The argument goes on a 10-bit input signal `n` (0 to 1,023), checked over that whole range. The returned integer goes on a 21-bit output `collisions` (0 to 2,097,151), which leaves room for large answers. The request names no exception, so `raises` is `[]` and the 2-bit `outcome` reads: 0 for a returned integer that fits, 1 for any exception or no answer, and 2 for anything else. There is one frame rule, F-ZERO (`outcome != 0 -> collisions == 0`). It cites R-FR-1, a verbatim quote from line 36 of `frame.md` that `fcp anchor` placed. `frame.md` gives the call encoding and the signal tables, and says that negative arguments and arguments above 1,023 are not part of the trace; it does not restate the request's rules. I set `design: review` to match the existing `requirements.yaml`. The draft I gave `fcp anchor` is still in the workspace as `draft.yaml`.
