I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `candidate(s)`, and `fcp lint` reports the bundle clean. Each call is one cycle. The argument `s` is an input string of up to 32 characters with codes 0–255 (8-bit slots, so `len(s)` and `s[i]` work), and the returned value is a 6-bit output `result` (0–63). `outcome` is 2 bits with `raises: []`, because the request names no exception: 0 means it returned an integer that fits, 1 means it raised any exception or did not finish, and 2 means it returned anything else, including a negative or too-large number. One decision needs your review: the request never says what the function returns, so I chose a non-negative integer, wide enough for any count over a 32-character word. `frame.md` says the request is silent on this. If you mean a different return type, `result` and `outcome` need to change, because right now any other return is coded as outcome 2. The `function` section declares `candidate` with one `str` argument and an `int` return. Its scope uses an alphabet of the vowels and `y` in both cases plus a few consonants, 3000 random strings, and short words around a final `y` (`y`, `ay`, `yay`, `sky`, `yes`, `day`, `ACEDY`). There is one frame rule, F-ZERO (`outcome != 0 -> result == 0`), which cites R-FR-1, a verbatim definition quoted from frame.md line 53 and anchored with `fcp anchor`. `frame.md` describes only the encoding: the call model, string indexing and character case, which values are left out of the trace (longer strings, non-strings, negative numbers), and the outcome codes. It doesn't restate the vowel rule. The `draft.yaml` used for anchoring is still in the workspace.
