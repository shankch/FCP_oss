I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `vowels_count(s)`, and `fcp lint` now reports clean. Each cycle after the reset in cycle 0 is one call with no state carried between calls. The argument `s` is a string input of at most 32 characters with codes 0 to 255, so longer strings and higher codes are not part of the trace. The returned integer goes on `count`, a 6-bit output (0 to 63), which covers every count a 32-character word allows plus the values just above it. The `outcome` signal is 2 bits; because the request names no exception, `raises` is `[]` and the codes are 0 (returned an integer that fits), 1 (raised any exception or did not finish) and 2 (returned anything else, including a negative number or one above 63); `frame.md` says negative numbers are not part of the trace. The scope uses an alphabet of upper- and lower-case vowels, `y` and a few consonants, 3000 random strings, and the two strings from the request's examples, `'abcde'` and `'ACEDY'`. There is one frame rule, F-ZERO (`outcome != 0 -> count == 0`); it cites R-FR-1, which quotes `frame.md` line 49 as computed by `fcp anchor` from `draft.yaml`, and I left that draft file in the workspace. `frame.md` describes only the encoding and does not restate the vowel rules, though it does mention that upper- and lower-case letters have different codes and that `lower(c)` and `upper(c)` map between them.
