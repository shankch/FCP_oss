I wrote `design.yaml` and `frame.md` for `candidate(s)` and added `R-FR-1` to `requirements.yaml`; `fcp lint` reports clean. Each cycle after reset is one call with no state kept between calls. The argument `s` is an input string of up to 32 characters with codes 0–255, and the output is `result`, 6 bits wide (0–63). The request doesn't give a maximum word length, so 32 is my choice; the count can't be larger than the length, so 6 bits leaves room for the values just past it. Because the request names no exception, `raises` is `[]` and `outcome` takes three values in 2 bits: 0 returned an integer that fits, 1 any exception or no answer, 2 returned anything else. The scope uses the request's two examples (`'abcde'`, `'ACEDY'`), 3000 random strings, and an alphabet of the vowels and `y` in both cases plus a few consonants (b, c, d, x, z), which I added as letters that aren't vowels. The one frame rule, `F-ZERO`, says `result` is 0 unless `outcome` is 0; `R-FR-1` quotes it verbatim with `lines: [50]` from `fcp anchor`, and I deleted the temporary `draft.yaml` afterwards. `frame.md` covers the call model, how strings are encoded, the input and output tables, the 32-character and code-255 limits, and that negative numbers aren't part of the trace. I named the output signal `result` rather than something like `vowels` because the request says "the number of characters or vowels", and the interface shouldn't settle which one it means.
