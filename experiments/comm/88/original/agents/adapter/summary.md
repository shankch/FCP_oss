I wrote `design.yaml`, `frame.md` and `requirements.yaml`, and `fcp lint` now reports `lint: clean`. Each call of `sort_array(array)` is one cycle after a reset in cycle 0, with no state kept between calls. The argument is the input list signal `array` and the return value is the output list signal `result`; both hold at most 8 integers from 0 to 255 (width 8, length 8), so the 7-element example fits. The request sets no limit on values or length, so 255 and 8 are bounds I picked. `outcome` is 2 bits with `raises: []`, since the request names no exception: 0 means it returned a list that fits, 1 means any exception or the call did not finish, and 2 means it returned anything else. The `function` section names the function, the list argument and return, the outcome, and a scope that uses the four example inputs plus elements 0–7, 254 and 255, with 3000 random calls. Lint accepted the list scope keys `elements` and `values`, but I'm not sure it checks their meaning, because I couldn't read the tool source outside the workspace. `frame.md` explains the list encoding and says that longer lists, values above 255 and negative integers are not part of the trace. It also says the trace records only values, so it cannot show whether the code changed the list passed in or returned that same object. That affects the request's "don't change the given array" note, which this interface cannot express.
