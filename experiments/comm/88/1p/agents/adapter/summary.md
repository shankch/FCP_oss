I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `sort_array(array)`, and `fcp lint` reports clean. Each cycle is one call of a function with no memory between calls. The argument `array` is an input list of up to 8 numbers from 0 to 255 (8 bits each). The returned list is an output, `result`, of the same size. The 2-bit `outcome` uses 0 for a returned list that fits, 1 for any exception or no answer, and 2 for anything else; `raises` is `[]` because the request names no exception. The `function` section declares a `list` argument and a `list` return. Its `scope` has elements 0–5, 254 and 255 plus 3,000 random lists, because the request gives no specific values. There is one frame rule, F-EMPTY (`outcome != 0 -> len(result) == 0`), which cites R-FR-1. That requirement quotes `frame.md` line 46, which `fcp anchor` found from `draft.yaml` (left in the workspace). `frame.md` explains calls, how lists are read in FCP-PL, and the inputs and outputs, and says negative numbers are outside the trace. The request allows any length and any size of number, so the limit of 8 elements up to 255 is my choice; you can raise it if formalizers need longer lists or bigger values.
