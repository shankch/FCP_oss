I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `largest_prime_factor(n)`, and `fcp lint` now reports "lint: clean". Each cycle after the reset in cycle 0 is one call with no state carried between calls. The argument goes on a 16-bit input `n`, covering 0 to 65,535. That width is my own choice, because the request sets no upper bound: it fits the doctest values 13195 and 2048, their neighbours, and the values just outside the request (0, 1 and primes). The result goes on a 16-bit output `factor`, the same width, so a returned `n` still fits. The request names no exception, so `raises: []` and the 2-bit `outcome` uses three codes: 0 returned an integer that fits, 1 any exception or no answer, 2 anything else. The scope covers `n` densely from 0 to 4100, plus 400 random values and 13195. `frame.md` covers the calls, the input and output tables, and the fact that negative or over-range arguments are not part of the trace, without restating the request's rules. It defines one frame rule, F-ZERO (`outcome != 0 -> factor == 0`), cited by R-FR-1 in `requirements.yaml` with a verbatim quote and `lines: [39]` from `fcp anchor`. The draft that anchor read is still in the workspace as `draft.yaml`.
