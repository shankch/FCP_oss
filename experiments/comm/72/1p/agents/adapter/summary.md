I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `will_it_fly(q, w)`, and `fcp lint` reports clean. Each cycle after reset is one call, with no state kept between calls. `q` is a list signal of at most 8 elements, each 0 to 255. `w` is 12 bits (0 to 4,095), which goes past the largest possible sum of `q` (8 × 255 = 2,040). These sizes are my choice, since the request sets no limits. The returned bool is a 1-bit `flies` signal. `outcome` is 2 bits: 0 means it returned True or False, 1 means it raised any exception or didn't finish, and 2 means it returned anything else; `raises` is `[]` because the request names no exception. The `function` section has a scope that includes the examples' lists `[1, 2]`, `[3, 2, 3]` and `[3]` and the weights 1, 5 and 9. `frame.md` explains the signals, lists, widths and outcome codes, and says that negative numbers, longer lists, larger values and non-integer elements are not part of the trace. It describes the interface only. The one frame rule, F-ZERO (`outcome != 0 -> !flies`), cites R-FR-1, a definition that quotes `frame.md` word for word at line 47 (placed there by `fcp anchor`).
