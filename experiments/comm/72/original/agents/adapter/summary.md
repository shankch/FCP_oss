I wrote `design.yaml`, `frame.md` and `requirements.yaml`, and `fcp lint` reports "lint: clean". Each cycle is one call of `will_it_fly(q, w)` on a function with no memory. `q` is a list signal of at most 8 slots of 8 bits (`type: list`, elements 0–255). `w` is a 12-bit integer (0–4,095), which covers the largest possible sum of `q` (8 × 255 = 2,040) and the values just above it. The returned bool goes on the 1-bit output `flies`. Because the request names no exception, `outcome` has `raises: []` and is 2 bits: 0 means it returned True or False, 1 means it raised any exception or didn't finish, and 2 means it returned anything else. The `function` section also has a `scope`. For `q` it uses the request's example lists ([1, 2], [3, 2, 3], [3]), elements 0, 1, 2, 3, 5, 9 and 255, and random lists. For `w` it uses the range 0–64 plus the example weights 1, 5 and 9. I picked those length and value limits myself because the request gives none. `frame.md` describes the calls, how a list is carried (including `len(q)` and `sum`), the input and output tables, and states that longer lists, larger values and negative numbers are not part of the trace. It doesn't restate the request's balance or weight rules. There is one frame rule, F-ZERO (`outcome != 0 -> !flies`), which cites R-FR-1, a verbatim definition quote from `frame.md` (line 46, computed by `fcp anchor` from `draft.yaml`, which is still in the workspace).
