I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `valid_date(date)`, and `fcp lint` reports clean. Each cycle after the cycle-0 reset is one call with no state kept between calls. The `date` argument is an 8-bit string signal of at most 16 characters, which covers the 10-character `mm-dd-yyyy` format, longer strings just outside it, and the empty string. The returned boolean goes on a 1-bit output, `valid`. The 2-bit `outcome` follows the examples: 0 means it returned True or False, 1 any exception or no answer, and 2 anything else. `raises` is `[]` because the request names no exception. The `function` section lists the name, the string argument, the bool return, the outcome and a `scope`: the alphabet `0123456789-/`, 3000 random strings, and the strings the request mentions (`''`, `03-11-2000`, `15-01-2012`, `04-0-2040`, `06-04-2020`, `06/04/2020`). `frame.md` explains the calls, the string encoding, and the input and output tables. It says that longer strings, characters above code 255 and negative numbers are not part of the trace. It states one frame rule, F-ZERO (`outcome != 0 -> !valid`), which cites R-FR-1 in `requirements.yaml`, a verbatim quote anchored to line 49 by `fcp anchor`. `fcp anchor` refused a draft from outside the workspace, so the draft is in the workspace as `draft.yaml` and is still there.
