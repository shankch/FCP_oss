I wrote `design.yaml`, `frame.md` and the R-FR-1 entry in `requirements.yaml` for `valid_date(date)`, and `fcp lint` reports clean. Each call after the reset cycle is one cycle of the trace, and the function keeps no state between calls. The `date` argument is a string signal of up to 32 characters (codes 0–255), which leaves room beyond common date formats. The returned bool is a 1-bit `valid` signal. `outcome` is 2 bits: 0 it returned True or False, 1 it raised any exception or did not finish, 2 it returned anything else. `raises` is `[]` because the request names no exception. There is one frame rule, F-ZERO (`outcome != 0 -> !valid`). It cites R-FR-1, which quotes `frame.md` line 49 as a definition; I got the line from `fcp anchor` and then deleted the temporary `draft.yaml`. `frame.md` says that longer strings, characters above 255 and non-string arguments, including negative numbers, are not part of the trace. The request in `spec.md` stops after "1.", so it gives no rules, formats or constants. The scope therefore has no `values`: it is random strings over digits plus `-` and `/` (my choice for a date string), and the tool adds the readings' and the code's own constants.
