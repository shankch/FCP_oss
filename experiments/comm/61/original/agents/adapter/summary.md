I've written `design.yaml` and `frame.md` for `correct_bracketing(brackets)`, and `fcp lint` reports the bundle clean. Each cycle is one call with no memory between calls. The argument is the input signal `brackets`, a string of up to 16 characters with any code from 0 to 255. That covers the brackets the request allows plus strings containing other characters, which sit just outside it. I picked 16 as the length limit because the request sets none, so no fixed length can cover every allowed string. `frame.md` says that longer strings, characters above code 255 and negative numbers are not part of the trace. The returned bool is the 1-bit output `result`. Since the request names no exception, `raises` is `[]` and `outcome` is 2 bits: 0 means it returned True or False, 1 any exception or no answer, and 2 it returned anything else. The `function` section declares the string argument and the bool return. Its scope uses the alphabet `()`, 3000 random calls, and the four example strings from the request (`(`, `()`, `(()())`, `)(()`). The docs are SPEC (`spec.md`) and FRAME (`frame.md`). There is one frame rule, F-ZERO (`outcome != 0 -> !result`), which cites R-FR-1 in `requirements.yaml`: a verbatim quote of `frame.md` of kind definition, with its line (48) filled in by `fcp anchor`.
