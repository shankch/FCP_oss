I wrote `design.yaml` and `frame.md` for `correct_bracketing(brackets)`, anchored the frame requirement into `requirements.yaml`, and `fcp lint` now reports `lint: clean`. Each cycle is one independent call. The argument goes on the input `brackets`, a string signal of at most 16 characters with codes 0–255, so the empty string and characters other than `(` and `)` are part of the trace. The returned bool goes on the 1-bit output `result`. The request names no exception, so `raises` is `[]` and the 2-bit `outcome` is 0 for a returned True or False, 1 for any exception or no answer, and 2 for anything else. `frame.md` says that longer strings, characters above 255 and negative integers are not part of the trace. The one frame rule, F-ZERO (`outcome != 0 -> !result`), cites R-FR-1, a definition quoting `frame.md` line 50. The `scope` uses the alphabet `()`, 3000 random strings, and the empty string plus the four doctest inputs. I chose the 16-character limit myself because the request sets no maximum length.
