I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `correct_bracketing(brackets)`, and `fcp lint` reports the bundle as clean. Each cycle after the reset in cycle 0 is one independent call. The `brackets` argument is an input string signal of up to 32 characters (codes 0–255, with any character allowed in the trace, not only `(` and `)`). The returned bool goes on a 1-bit `result` output. Because the request names no exception, `raises` is `[]` and the 2-bit `outcome` is coded 0 for a returned bool, 1 for any exception or no answer, and 2 for anything else returned. The `function` section has a scope using the alphabet `()`, 3000 random strings, and the values `'('`, `')'` and `''`. Both docs are listed: SPEC (`spec.md`) and FRAME (`frame.md`). There is one frame rule, F-ZERO (`outcome != 0 -> !result`), which cites R-FR-1: a definition quoting `frame.md` line 49, with the line computed by `fcp anchor` from `draft.yaml`, which I left in the workspace. The 32-character limit is my own choice, because the request puts no bound on string length; calls with longer strings are not part of the trace, and `frame.md` says so. `frame.md` describes only the encoding and doesn't restate the bracketing rule; it has no line about negative integers because there are no integer signals.
