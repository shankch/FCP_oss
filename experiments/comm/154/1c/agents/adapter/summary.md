I wrote `design.yaml`, `frame.md` and `requirements.yaml` for `cycpattern_check(a, b)`, and `fcp lint` now reports `lint: clean`. The two arguments are string inputs `a` and `b` (8-bit characters, codes 0 to 255, at most 16 characters each). The prompt sets no length limit for a "word", so 16 is my own choice: it covers the longest example word (7 characters) and the lengths just past it, and keeps checks that loop over both strings small. The returned bool goes on a 1-bit `result` output. The 2-bit `outcome` uses 0 for a returned bool, 1 for any exception or no answer, and 2 for anything else returned; `raises` is `[]` because the prompt names no exception. There is one frame rule, F-ZERO (`outcome != 0 -> !result`), which cites R-FR-1, a definition quoting line 52 of `frame.md` that `fcp anchor` filled in. The `function` section's scope uses the docstring's example words as values (first words for `a`, second words for `b`), with alphabet `'ab'` and 2000 random strings per argument. `frame.md` explains the calls, the string encoding in FCP-PL, the input and output tables, and that longer strings, characters above 255, non-string arguments and negative numbers are not part of the trace. It describes only the interface, not the prompt's rules. Two other things: `fcp anchor` refused a draft from outside the workspace, so `draft.yaml` stays in the workspace, and I set `design: review` to match the `requirements.yaml` that was already there.
