I wrote `design.yaml` and `frame.md` for `cycpattern_check(a, b)`, added the one frame requirement to `requirements.yaml`, and `fcp lint` reports clean. Each call is one cycle of a function with no memory. The two arguments `a` and `b` are input strings of at most 12 characters, codes 0 to 255; I picked that length myself because the request sets no limit and its longest example word has 7. The returned bool goes on a 1-bit `result` signal. The request names no exception, so `raises` is `[]` and the 2-bit `outcome` uses 0 for a returned bool, 1 for any exception or no answer, and 2 for anything else. The `function` section has the name, the two `str` arguments and the bool return. Its `scope` uses the six word pairs from the request's examples, plus random strings over a two-letter alphabet; I added that so that rotation matches turn up often. `frame.md` describes the calls, the string encoding, and the input and output tables. It says longer strings are not part of the trace, and that every argument is a string so negative numbers don't come up. It also notes that no outcome code is reserved for an exception. Its single frame rule, F-ZERO (`outcome != 0 -> !result`), cites R-FR-1, a verbatim quote of `frame.md` line 49 that `fcp anchor` computed.
