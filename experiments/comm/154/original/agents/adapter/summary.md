Each cycle of the trace is one call of `cycpattern_check(a, b)`, with a reset at cycle 0 and no state kept between calls. The two arguments are 8-bit string inputs (`a`, `b`) of at most 12 characters each. I picked 12 myself, because the request puts no limit on word length: the longest example word has 7 characters, and a larger bound would make the formal checks much slower. The returned bool is a 1-bit output `result`. Since the request names no exception, `raises` is `[]` and the 2-bit `outcome` is coded 0 returned True or False, 1 any exception or no answer, 2 returned anything else. The `function` section declares both arguments as `type: str`. Its `scope` uses the example words from the request (a: abcd, hello, …; b: abd, ell, …), a small alphabet `ab` so random calls often produce rotations that match, and 3000 random strings per argument. `frame.md` explains the calls, how strings are encoded in FCP-PL, the input and output tables, that longer strings, characters beyond code 255 and negative integers are not part of the trace, and the one frame rule F-ZERO (`outcome != 0 -> !result`).
