I wrote `design.yaml` and `frame.md` for `parse_duration(text: str) -> int`, and `fcp lint` now reports clean. Each cycle after the reset cycle is one call. The argument is an input string signal `text` of at most 16 characters (Latin-1 codes 0–255), which leaves room well past the longest duration the request allows. The returned number goes on a 19-bit `seconds` output (0 to 524,287), wide enough to record any total built from numbers up to 99 in each unit rather than folding it into "returned anything else". The 2-bit `outcome` is coded as in the examples: 0 returned an integer that fits, 1 raised `ValueError`, 2 any other exception or no answer, 3 anything else. The `function` section lists the name, the one string argument, the int return, the outcome with `raises: [ValueError]`, and a scope with the characters `0-9`, `h`, `m`, `s` and space plus the values `'1h30m'`, `'45s'` and `''`. The docs are SPEC (spec.md) and FRAME (frame.md), and there is one frame rule, F-ZERO: `seconds` is 0 unless `outcome` is 0. `frame.md` covers calls, strings in FCP-PL, the input and output tables and that rule, and doesn't restate the request's rules. One change outside the two files: lint rejected the frame rule because it cites `R-FR-1`, and `requirements.yaml` was empty.
