I wrote `design.yaml` and `frame.md`, and `fcp lint` now reports clean. The design models `GiftCard` as an object with three methods: a reset creates `GiftCard()`, and each later cycle calls one method on it. A 2-bit `op` input picks the method (1 `load`, 2 `spend`, 3 `balance`). `load` and `spend` share a 16-bit `amount` input, which covers 0 to 65,535, including 0 and 50,001 just outside the allowed amounts. Each method returns on its own output: `bonus` (16 bits) for `load`, `spent` (1 bit) for `spend`, and `balance` (16 bits) for `balance()`. A 2-bit `outcome` is coded as in the examples (0 returned, 1 `ValueError`, 2 other exception or no answer, 3 anything else). Two frame rules say the results are 0 unless `outcome` is 0 (F-ZERO) and each result is 0 when another method is called (F-OTHER). frame.md explains the calls, the signals and these rules, and notes that the card's balance is not a signal and that only `op` tells `balance()` apart from `load(0)` or `spend(0)`. The scope is 4,000 call sequences of 1 to 14 calls, with amounts drawn from the request's figures and their neighbours. Two things are guesses: the request doesn't name a file, so I set `module: gift_card`, and I made `bonus` 16 bits so it would fit even if the bonus is read as earned per $100 rather than per load. To get past the lint I also had to add the two frame requirements (R-FR-1, R-FR-2, quoting frame.md) to the empty `requirements.yaml`, with line numbers set by `fcp anchor`.
